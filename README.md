# VPlayer

一个 Chrome / Edge 的 Manifest V3 插件：发现网页里的 HLS 视频，在独立播放页并发预加载后续分片，使用本地磁盘缓存减少网络波动带来的等待。

## 安装

已构建的插件在 `dist/`，可以直接加载，不需要运行开发服务器。

1. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本项目的 **`dist` 文件夹**，不是项目根目录。
4. 把 VPlayer 固定在浏览器工具栏。

若使用 ZIP 包，先解压，再选择包含 `manifest.json` 的目录。插件尚未发布到应用商店。

## 使用

1. 在原网页播放视频。已经打开的网页建议刷新一次，让插件观察到播放列表请求。
2. 点击工具栏的 VPlayer，选择发现的视频源。
3. 视频在独立标签页播放，并尝试暂停原网页的视频，关闭插件弹窗不会中断播放。
4. 没有自动发现时，也可以在弹窗中粘贴 HTTP / HTTPS m3u8 地址。

### 选集与换源（v0.2）

v0.2.1 修复旧播放会话缺失原网页标签页关联、导致选集为空且刷新按钮不可用的问题：根据已保存的网页地址重新关联已打开的原网页；优先扫描主页面，不让无关子页面阻断读取；显示明确的读取失败原因。真实教父第 4 集页面已验证识别 11 条线路、33 集。

**更新文件后必须在扩展管理页点击重新加载。** 仅刷新播放器，可能让新界面配合旧版后台运行，选集信息仍然缺失。若扩展重新加载后旧播放会话已失效，从原网页重新打开即可。

从原网页的视频源列表打开播放器时，会同时读取网页的选集和播放线路。播放器下方的「选集与换源」支持：

- 点击集数，以及上一集 / 下一集。
- 切换播放线路：按显示的集数匹配同一集，并保留当前播放位置。不同版本的片头或剪辑时长可能需要手动微调。
- 线路缺少当前集时，明确提示并让用户选择，不把第几个链接误当成第几集。
- 刷新选集列表、取消正在进行的切换。新地址获取失败时，当前视频继续播放。

已处理两种页面结构：555 的 `/vodplay/作品-线路-序号.html` 多线路分组，以及教父的 `/py/线路/集数` 数字选集 + 原生下拉线路。555 的列表解析使用所提供页面的实际选集 DOM 做回归测试；教父的已登录页面结构通过浏览器确认，切换行为使用同结构的本地页面验证。特殊改版或其他网站仍可能需要适配。

选集时，插件为当前播放器创建并复用一个**不抢焦点、已静音的后台标签页**，让原网站使用浏览器现有登录状态生成真实视频请求。获取到对应 m3u8 后，暂停后台页的视频并接入当前播放器。原网页不会被改为其他集；关闭播放器后，会关闭插件创建的后台页。网站要求额外登录或验证时，播放器会提示检查原网页。

直接粘贴 m3u8 不包含剧集目录，因此不会凭空生成选集。升级后，请在扩展管理页刷新 VPlayer，再从原网页重新打开播放器，旧播放页不会自动获得新界面。

默认 4 路并发、提前缓存 2 分钟、优先选择不高于 720p 的画质。可改为 1 / 2 / 4 / 6 / 8 路并发，以及 30 秒 / 2 分钟 / 5 分钟预加载窗口。高码率视频或内存缓存模式下，会按缓存容量缩短实际预加载窗口，避免反复淘汰、下载同一批分片。画质手动选择：缓存命中的读取速度不会用来自动提升画质。

暂停视频后会继续填充预加载窗口。关闭「预加载后续分片」会停止额外预加载，播放器正常播放仍会下载所需分片。拖动进度或切换画质后，远处的预加载任务会取消，优先准备新的播放位置。

## 指标的含义

- **下载速度**：最近 5 秒内收到的分片字节数 / 5，不包含播放列表和密钥请求；包含下载失败前已接收的字节。
- **可播放缓冲**：浏览器媒体缓冲里、从当前位置起连续可播放的秒数。
- **连续本地缓存**：磁盘缓存中连续可用的媒体分片时长；有独立音轨时取音视频较小值。它不代表密钥和 DRM 许可可离线使用。
- **缓存命中**：播放请求直接读取本地分片缓存的次数。
- **播放等待**：首次播放后浏览器报告的等待事件次数，不计首次启动和主动拖动进度。

网络下载与媒体播放缓冲分开管理：每个播放会话最多缓存 512 MB 压缩分片；浏览器媒体缓冲保留近期内容。达到缓存上限时淘汰较久未使用的分片。IndexedDB 不可用或配额不足时降级为最多 32 MB 内存缓存。旧会话的磁盘数据在 24 小时后、下次打开播放页时清理；「清除」按钮清除当前视频缓存。当前版本没有离线视频库或整部下载按钮。

## 支持范围

- Chrome / Edge 桌面版（Chromium 120+）；没有为 Firefox / Safari 打包。
- 普通 HLS 点播和直播、主播放列表、多画质、独立音轨。
- TS / fMP4 分片、初始化分片、HTTP Byte Range；具体编码仍取决于浏览器。
- 普通 HLS AES-128 由 hls.js 处理；不支持 DRM 授权播放。
- `.m3u8` 地址和以 HLS MIME 类型响应的无扩展名地址都可以发现。
- 播放请求携带浏览器允许发送的 Cookie；捕获到的 Referer / Origin 只通过当前播放标签页的临时规则设置。Authorization 仅用于与播放列表同源的请求，不向其他 CDN 域名转发。

不是每个网站都能接管播放：链接过期、Cookie 分区、一次性签名、网站特殊鉴权、DRM、非 HLS 源都可能需要站点适配。插件不会提取 `blob:` 对应的媒体对象，也不绕过 DRM。直播未来的分片尚未产生，不能提前下载。

并发数是分片下载上限，不是总 HTTP 请求上限；播放列表、字幕和密钥由 hls.js 单独加载。增加并发不能突破总带宽或服务端限速。建议用同一视频分别比较 1、4、8 路的下载速度、连续缓存和等待次数。

## 权限与数据

- `webRequest` 与 HTTP/HTTPS 网站权限：观察视频请求，识别播放列表，并在插件播放页跨域下载分片。
- `activeTab`：用户打开插件时显示当前网页标题。
- `scripting`：读取原网页选集和线路；在插件创建的后台页执行用户选中的选集 / 线路操作；接管播放后暂停网页视频。
- `storage`：在浏览器内保存设置、会话和发现结果。
- `declarativeNetRequestWithHostAccess`：为当前播放页恢复捕获的 Referer / Origin，关闭播放标签页后移除规则。

无遥测、无远程脚本、无外部字体、无云端中转。视频地址和请求凭据仅保存在浏览器会话中；媒体数据保存在插件自己的 IndexedDB 中。插件只会联系视频播放需要的源站，不会把这些信息上传到其他服务。

## 开发与验证

需要 Node.js 20+。浏览器集成测试还需要 `ffmpeg`。

```sh
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

`npm run check` 依次执行单元测试、构建和浏览器集成测试。集成测试使用临时浏览器配置，不会修改日常浏览器的设置。测试在本机生成 H.264/AAC HLS 视频，用要求 Cookie、Referer、Authorization 的本地源验证捕获、播放、并发、缓存与拖动，并覆盖 HTTP 错误与响应式布局。

测试截图和结果写入 `artifacts/`。前端依赖和 hls.js Worker 均在构建时打包到 `dist/`，符合 Manifest V3 的本地脚本要求。hls.js 的许可随插件放在 `HLS-LICENSE.txt`。

## 代码结构

```text
src/background.js   请求发现、临时会话与播放请求头
src/popup.js        视频源列表和地址输入
src/player.js       播放界面、画质与预加载窗口
src/scheduler.js    优先级队列、并发、取消、重试与去重
src/cache.js        IndexedDB 缓存、淘汰与内存降级
src/loader.js       hls.js 分片加载适配
src/episodes.js     原网页选集、线路及媒体提示读取
src/episode-resolver.js  后台页面解析、取消与清理
src/episode-controls.js  选集与换源界面
tests/              调度器与浏览器集成测试
```
